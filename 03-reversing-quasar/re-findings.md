# Реверс `maind` через IDA Pro — находки

**Инструмент:** IDA Pro 9.4 + ida-pro-mcp (подключён к Claude Code).
**Бинарь:** `artifacts/maind`, SHA-256 `459679b2…7919a`, база в IDA `0x0`
(VA == file offset в первом LOAD-сегменте — удобно для якорения по строкам).

> Замечание по среде: на MCP-вызов действует лимит ~1 c. Мелкие функции (≤~2 КБ)
> декомпилируются нормально; для крупных (pinning-verify, диспетчер директив) поднят
> `MCP_TOOL_TIMEOUT` в `.claude/settings.json` (нужен рестарт сессии).

## 1. Модель доступа glagol (локальное управление, порт 1961)

Кластер мелких функций `0xD630xx` строит запросы к бэкенду и разбирает ответы.

| Функция | Запрос | Разбирает в ответе | Смысл |
|---|---|---|---|
| `sub_D63070` | `GET /glagol/token?device_id=<id>&platform=<p>` | `token` | получить glagol-токен устройства |
| `sub_D632B8` | API `check-token` → `/glagol/check_token` (v1) | `valid` (bool) | проверка токена |
| `sub_D63538` | API `check-token` → `/glagol/v2.0/check_token` (v2) | `owner`, `guest`, `puid` | проверка + роль и passport-uid |

**Ключевой вывод:** входящий glagol-токен валидируется **через облако Яндекса**
(`quasar.yandex.net/glagol/…`), а не локально на устройстве. Чтобы слать команды колонке
по LAN на :1961, нужен токен, признаваемый бэкендом для данного `device_id` (выдаётся из
привязанного аккаунта). То есть локальный канал не «offline»-доверенный — он завязан на
серверную проверку прав (owner/guest).

Фрагмент `sub_D63070` (псевдокод, сокращённо):
```c
build_url(&url, base, "/glagol/token?device_id=");
append(&url, device_id);
append(&url, "&platform=");
append(&url, platform);
http_get(resp, ctx, "token", 5, &url, ...);   // вытащить поле "token"
```

Фрагмент `sub_D63538` (v2 check_token): из JSON-ответа читаются `owner`/`guest`/`puid`
через `get_bool(..,"owner",5)`, `get_bool(..,"guest",5)`, `get_str(..,"puid",4)`.

## 2. Cert pinning (локализовано, нужен крупный декомп)

Строки-якоря:
- `0x25bd81` — `"SSL public key does not match pinned public key"` (прикладная)
- `0x3186bf` — `"SSL: public key does not match pinned public key"` (регистрируется в error-стек)

Обе ссылаются из таблиц указателей (данные), не из кода напрямую. Ближайшая крупная
функция, пушащая «SSL:»-строку — `sub_87BF70` (размер `0x3078` ≈ 12 КБ) — кандидат на
кастомный verify-callback BoringSSL (пиннинг SPKI). Декомпиляция требует поднятого
таймаута. Рядом — стандартные символы `X509_PUBKEY_get0/decode` (разбор публичного ключа
сертификата). План: декомпилировать `sub_87BF70`, найти сравнение SHA-256(SPKI) с
зашитым пином → точка обхода (патч/Frida-хук), т.к. root на устройстве уже есть.
